## 1. 产品目标和使用场景

**目标**：让一名大学生用手机和电脑在同一个网址上管理课程、日程、科研进度和健身记录，数据实时互通，不需要注册登录。

**使用者**：一个人。没有第二类角色，不存在协作、共享、权限分级。

**典型场景**

| 场景 | 设备 | 要完成的事 |
|---|---|---|
| 早上出门前扫一眼今天要干什么 | 手机 | 看今日课程、待办、最近截止日 |
| 在教室里记录作业截止日和组会安排 | 手机 | 30 秒内新增一条日程 |
| 周日晚排下周计划、录入新课 | 电脑 | 课表与日程的完整编辑 |
| 推进科研任务，标记里程碑完成度 | 两者 | 更新里程碑与子任务 |
| 练完顺手记一笔 | 手机 | 快速打卡并写入时长 |

**成功判据**：在任一设备上做出的改动，另一设备刷新后立刻可见；从打开网页到记录一条健身不超过约 10 秒。

## 2. 整体页面框架和导航结构

### 2.1 页面清单

| # | 页面 | 路由 | 性质 |
|---|---|---|---|
| 1 | 首页 · 任务舱 | `#/` | 只读聚合 |
| 2 | 课表 | `#/timetable` | 读写 |
| 3 | 日程 | `#/tasks` | 读写 |
| 4 | 科研 | `#/research`、`#/research/:id` | 读写 |
| 5 | 健身 | `#/workout` | 读写 |
| 6 | 设置 | `#/settings` | 读写 |

### 2.2 导航结构

- **桌面（≥1024px）**：左侧固定图标栏（展开 208px / 收起 72px，状态记本地），顶栏显示日期、学期周次、设置入口，内容区最大宽 1240px 居中。
- **移动（<640px）**：底部 5 个 Tab（首页 / 课表 / 日程 / 科研 / 健身），顶栏压缩为一行；设置从首页右上角齿轮进入。
- **平板（640–1023px）**：移动结构 + 内容区双列卡片。
- 断点统一使用 640 / 1024 两个值；导航状态存浏览器本地，不入云。

### 2.3 全局交互约定（所有页面共用）

1. 新建与编辑一律使用浮层：桌面居中 Modal（520px，内部滚动），移动底部抽屉（下拉关闭）。不使用整页跳转表单。
2. 写操作采用乐观更新：先改界面再写云，失败回滚并给出可重试的错误提示。
3. 删除：移动端列表项左滑，桌面端悬停出现图标； Toast 内 5 秒可撤销。仅科研的级联删除需要二次确认框。
4. 状态齐备：空状态（图标 + 引导语 + 主按钮）、加载骨架屏（不用转圈）、错误态（含重试）。
5. 桌面快捷键：`N` 新建、`Esc` 关闭浮层、`1`–`6` 切页。
6. 表单失焦即校验，无效时提交按钮禁用，不弹整体报错。

### 2.4 视觉规范（深空驾驶舱）

- 底色 `#070B14`，面板 `#0E1524`，1px 细描边 `#1E2B45`，背景细星点
- 强调色：青 `#3DD6F5`（进行/当前）、橙 `#FF8A3D`（临期/警告）、绿 `#4ADE80`（已完成）、灰 `#8FA3C0`（次要信息）
- 数字与标签用等宽字体栈，标题用系统无衬线；HUD 式角标、进度环、虚线分隔
- 触控目标 ≥ 44px；动效仅用于状态切换，不做视差与漂浮动画；只有深色一套主题

## 3. 首页的内容结构

首页不存任何业务数据，只把各模块的数据按"今天"聚合展示。

```
┌─────────────────────────────────────────────┐
│ A. HUD 状态条（整行）                        │
│   日期与星期 · 第 N 周/共 M 周               │
│   今日完成进度环（已完成待办 / 今日全部）     │
│   下一站：最近一个未完成截止项 + 剩余天数     │
├──────────────────┬──────────────────────────┤
│ B. 今日课程       │ C. 今日待办               │
│  按时段竖排      │  勾选框 + 标题 + 时间      │
│  当前时间指示线   │  逾期项排最前并标橙色      │
├──────────────────┼──────────────────────────┤
│ D. 近期里程碑     │ E. 本周健身               │
│  进度条 + 剩余天  │  次数 / 时长 / 连续天数    │
└──────────────────┴──────────────────────────┘
```

- 桌面 2×2 卡片，移动单列纵向滚动且每卡只显示前 2 条。
- 每张卡右上角「查看全部 ›」跳到对应模块页。
- 「下一站」取值规则：日程里 `due_date` 最早且未完成的一条；没有则取科研里 `target_date` 最近且未完成的里程碑；都没有则整块显示"今天没有到期事项"。

### 3.1 文字概念图（首页）

深空黑蓝底上一块块半透明仪表面板。顶部一条横向读数带，中间一枚发青光的环形进度表，下方四块矩形面板各自列着数据，细瘦等宽字体，关键数字放大且为青色，临期项泛橙光。留白充足、边框极细、无装饰插画。

## 5. 每个模块第一版最必要的数据和操作

### 5.1 课表

**数据**：课程名、教师、上课地点、星期几（1–7）、开始时间、结束时间、生效起止周、周型（每周 / 单周 / 双周）、颜色、备注。

**操作**：手动新增（表单，点击空白时段可预填星期与时间）、编辑、删除、按周次切换查看、网格/日/列表三视图切换。

**规则**
- 无拖拽改课，全部通过表单编辑（已定稿）。
- 周次切换时，不在该周生效的课程以 30% 透明度画出，便于理解"这周为什么没课"。
- 同一星期同时段重叠视为冲突：保存时给橙色警告并列出冲突课程，允许强制保存；已存在的冲突在网格上红描边并排显示。
- 13 门课规模，默认显示本学期当前周。

### 5.2 日程

**数据**：标题、截止日期、截止时间、预计时长（分钟）、分类（作业/科研/生活/其它）、备注、完成状态、完成时间、创建时间。

**操作**：新增、编辑、删除、勾选完成/取消完成、按今日/本周/全部/已完成分段查看、按分类与状态筛选。

**规则**
- 无重复规则（已定稿，见第 9 节）。
- 逾期项：左侧橙红竖条 + 「逾期 N 天」，提供「顺延到今天 / 明天 / 下周」。
- 列表按日期分组，分组标题吸顶；已完成项沉到各组底部并划线。
- 允许无日期的条目（收集箱），供快速记一笔后归类。

### 5.3 科研

**数据**：项目（名称、说明、状态、排序）；里程碑（所属项目、标题、目标日期、状态、进度百分比、进度是否手动设定、排序、备注）；子任务（所属里程碑、标题、完成状态、排序）。

**操作**：项目增删改；项目详情内里程碑增删改、里程碑拖拽排序（移动端用上/下按钮）；子任务增删改与勾选。

**规则**
- 里程碑进度默认 = 子任务完成比例自动计算并锁定；点锁图标可解锁手填，显示「手动」徽标，解锁后不再被自动值覆盖。
- 状态四态：未开始（灰）/ 进行中（青）/ 阻塞（橙）/ 已完成（绿）。
- 删除里程碑需二次确认并写明"其下 N 个子任务会一并删除"。

### 5.4 健身

**数据**：日期、运动类型、时长（分钟）、完成度（完成 / 部分 / 缺练）、备注。

**操作**：新增记录（默认今天，类型 chips + 快捷时长 15/30/45/60/90，可 ±5 分钟微调）、编辑、删除；统计视图按本周/本月/自定义区间切换；日历热力视图。

**规则**
- 类型预设：跑步、力量、游泳、球类、骑行、瑜伽、其它；"其它"允许自定义命名并进入下次候选。
- "缺练"也是一条记录，用于保持时间线连续。连续天数规则：缺练当天归零，部分完成不清零。
- 统计口径：本周/本月次数与总时长、类型分布、连续打卡天数、近 8 周时长趋势。

### 5.5 设置

**数据**：学期起始日、总周数、节次时间表（每节名称、开始、结束，或标记为午休留空带）。

**操作**：编辑学期与节次（保存前预览"第 N 节将从 X 移到 Y，影响 M 门课"）、导出全量 JSON、导入 JSON（先做结构校验并给冲突报告）、清空全部数据（需输入 `DELETE` 确认）。

**规则**：节次表是课表纵轴的来源，改动即时影响课表网格行位。首次使用给一份国内常见节次模板 + 一个学期起始日输入，5 秒可完成初始化。

## 6. 首页、今日计划与各模块之间的关系

```
课表 courses ─┐
日程 tasks ───┼─► 按"今天"过滤 ─► 首页 HUD 状态条 + 四分区卡片（只读）
里程碑 ───────┘        │
健身 workouts ──► 本周聚合 ─┘

设置 semester_config ──► 周次计算与节次坐标轴 ──► 同时影响 首页状态条 / 课表网格 / 逾期判定
```

- **首页是派生视图，不是数据源**。唯一能在首页改的数据是待办的完成勾选，改动直接落到日程模块的数据上。
- **今日课程** = `courses` 中 `day_of_week = 今天` 且今天落在 `start_week..end_week` 且符合周型（单/双/每周）的课程，按开始时间升序。
- **今日待办** = `tasks` 中 `due_date = 今天` 或已逾期的未完成项，逾期优先、再按时间升序。
- **近期里程碑** = 全部项目中未完成的里程碑里 `target_date` 最近的 3 个。
- **本周健身** = `workouts` 中本周一至今日的聚合值。
- 学期周次公式：`floor((今天 - 学期起始日) / 7) + 1`，单双周由该周次的奇偶决定。

## 7. 云端数据存储方案

### 7.1 技术方案

- **部署形态**：静态前端（HTML/CSS/原生 ES Module，无框架、无打包步骤）+ 平台 Edge Function 作为唯一后端 + 平台托管的云数据库（Postgres/Supabase 系）。
- **访问链路**：浏览器只同源调用 `/functions/v1/app`，由 Function 读写数据库。数据库地址与密钥只存在于服务端运行时，不进入任何浏览器产物。
- **应用鉴权**：站点级访问控制（非公开模式，由平台网关在转发请求前校验访问者），替代注册登录。
- **待你确认的一项**：平台数据库策略仅支持 deny / public / owner 三档，owner 档要求 Supabase `auth.uid()`，而本平台 Function 拿不到它。因此可行方案是库表策略设 public、真实门禁放在站点网关。**未覆盖的风险是绕过站点直连数据库服务商**，需在开工前由你明确接受该范围（见文末附注）。

### 7.2 表结构（7 张表，字段名即数据库列名）

只使用平台支持的列类型：`uuid / text / integer / boolean / timestamptz / jsonb`。日历日期一律用 `text` 存 `YYYY-MM-DD`，时刻用 `text` 存 `HH:MM`。不使用外键、默认值与 CHECK（平台迁移接口不支持），完整性由 Function 校验。

```
app.semester_config      id uuid PK, start_date text, total_weeks integer,
                         periods jsonb, updated_at timestamptz
                         -- periods: [{label,start,end,kind:"class"|"break"}]

app.courses              id uuid PK, name text, teacher text, location text,
                         day_of_week integer, start_time text, end_time text,
                         week_type text('all'|'odd'|'even'),
                         start_week integer, end_week integer,
                         color text, note text, sort integer,
                         created_at timestamptz, updated_at timestamptz

app.tasks                id uuid PK, title text, due_date text, due_time text,
                         duration_min integer, category text, note text,
                         done boolean, done_at timestamptz,
                         created_at timestamptz, updated_at timestamptz

app.research_projects    id uuid PK, name text, description text, status text,
                         sort integer, created_at timestamptz, updated_at timestamptz

app.milestones           id uuid PK, project_id uuid, title text, note text,
                         target_date text, status text, progress integer,
                         manual_progress boolean, sort integer,
                         created_at timestamptz, updated_at timestamptz

app.subtasks             id uuid PK, milestone_id uuid, title text,
                         done boolean, sort integer, created_at timestamptz,
                         updated_at timestamptz

app.workouts             id uuid PK, workout_date text, type text,
                         duration_min integer, status text('done'|'partial'|'missed'),
                         note text, created_at timestamptz, updated_at timestamptz
```

索引：`courses(day_of_week)`、`tasks(due_date)`、`workouts(workout_date)`、`milestones(project_id)`、`subtasks(milestone_id)`。

数据规模上限：单人使用，每表预计 < 500 行；一次全量拉取即可，第一版不做分页。

### 7.3 Function 接口契约

| 动作 | 方法 | 入参 | 返回 |
|---|---|---|---|
| `bootstrap` | GET | 无 | 7 张表全量 + `serverTime`（统计口径只在 `web/lib/time.js` 一处实现，见 DEV_PLAN S2 修订） |
| `create` | POST | `{table, row}` | 落库后的完整行 |
| `update` | POST | `{table, id, patch}` | 更新后的完整行；无匹配行返回明确错误 |
| `remove` | POST | `{table, id}` | 被删行的 id |
| `import` | POST | 全量快照 | 各类记录的写入条数与冲突报告 |
| `wipe` | POST | `{confirm:"DELETE_ALL"}` | 各表清空条数 |

- ID 与时间戳由 Function 生成，不接受浏览器传入的 `id`/`created_at` 覆盖。
- 每张表在 Function 内维护**列白名单 + 逐字段校验**（类型、长度上限、枚举集合、`YYYY-MM-DD` 与 `HH:MM` 正则、整数范围），请求体大小设上限，GET 不改变任何状态。
- 数据库原始错误只留在服务端，浏览器只看到固定的应用错误码；前端把错误码映射成中文提示。

### 7.4 手机与电脑数据一致性

1. **单一真源**：数据库是唯一可信状态。浏览器本地只存 UI 偏好（侧栏开合、视图选择、卡片顺序），不存业务数据，因此不存在"本地攒了一份再同步"的冲突模型。
2. **读取时机**：每次进入页面、切到前台、下拉刷新、写操作成功后，都重新拉 `bootstrap` 或该表数据；不做跨会话的缓存复用。
3. **写入语义**：乐观更新只负责界面即时响应，**以服务端返回的行为准**并回填。写入失败回滚原状并提供重试。
4. **响应丢失**：网络错误导致的写入不自动重放（避免重复插入），提示"结果未知，请刷新确认"，刷新后以服务端为准。
5. **并发覆盖**：同一账号两台设备同秒改同一条记录时，后写入者覆盖前一位，第一版接受这一行为（单人使用，概率极低），所有表保留 `updated_at` 以便后续引入冲突检测。
6. **时间口径**：周次、今日、连续天数等按浏览器本地时区计算，避免"手机与电脑跨时区"导致日期错位；数据里存的是日历日期与钟表时刻字符串，不做时区换算。
7. **兜底**：`导出 JSON / 导入` 提供人工恢复路径，前端解析异常时可用它重建。

### 7.5 各页面文字概念图（视觉方向备查）

- **课表**：深色发光的周计划网格，像飞行任务时间轴面板；纵轴密集时刻刻度，横轴七天，课程为半透明色块贴附网格、边缘有细光线，当前时刻一条青色虚线横穿全屏。
- **日程**：深色任务清单面板，按日期分节、节标题像舱段编号；方形勾选框，逾期行左缘发橙红光，已完成行整行变暗并划掉，侧边筛选栏像控制面板。
- **科研**：任务规划板；项目为矩形舱段卡片内含水平进度刻度，详情是纵向发光时间线，节点为空心/实心圆环，选中节点向右展开方形勾选框子任务清单。
- **健身**：遥测面板；大数字仪表用青色等宽字体，环形分量图与柱状趋势像燃料与遥测读数，未训练日为暗灰空格带细线。
- **设置**：工程图纸式表单，网格底纹、虚线分隔、节次行是可增删的技术条目。

## 10. 可实际检查的验收标准

在**已部署的网址**上执行，桌面 Chrome + iPhone Safari 各一遍。

**门禁与连通**
- C1：手机与电脑访问同一网址，都进入应用；未授权访客访问时看不到任何业务数据。
- C2：桌面端调整窗口到 375px 宽，导航自动变为底部 Tab，无横向滚动条、文字不截断。

**数据互通（核心）**
- C3：手机新增一条日程「验收测试项 A」→ 电脑点刷新，该项出现；电脑勾选完成 → 手机刷新后显示已完成。
- C4：电脑新增一门课（星期三 10:00–11:40，单周，第 3–15 周）→ 手机切到对应单周周次，该课出现在正确位置；切到双周周次，它以 30% 透明度显示。
- C5：手机与电脑**同时**打开首页，在其中一台勾选一条待办，另一台不刷新页面、仅切到前台或下拉一次即可看到最新状态。

**课表**
- C6：录入 13 门课（含至少 2 门单周、2 门双周、1 门只在第 1–8 周）后，第 5 周视图与第 12 周视图的显示结果与实际情况一致。
- C7：新增一门与已有课时间重叠的课，保存前出现橙色冲突警告并列出冲突课名；强制保存后网格中两课并排且红描边。
- C8：网格 / 日 / 列表三视图切换后回到原视图，刷新页面仍保持上次选择的视图。

**日程**
- C9：把一条待办截止日期设为昨天，它在首页与日程页均显示「逾期 1 天」且为橙色左边框；点「顺延到明天」后消失于逾期分组。

**科研**
- C10：项目 A 下建 2 个里程碑、其中一个建 4 条子任务，勾掉 2 条 → 该里程碑进度显示 50%；解锁手调为 80% 后显示「手动」徽标；再勾掉 1 条子任务，进度仍保持 80% 不被自动值覆盖。
- C11：删除含 3 条子任务的里程碑时，确认框文案写明会一并删除 3 个子任务，确认后子任务同时消失。
- C12：拖拽调整里程碑顺序（移动端用上/下按钮）后刷新，顺序保持。

**健身**
- C13：连续记录 3 天训练、中间插入一天「缺练」，连续天数应归零重算；「部分完成」不中断连续。
- C14：本周累计 3 次共 185 分钟时，首页「本周健身」与健身页统计数字完全一致。
- C15：从点开「记一笔」到保存成功，全程 ≤ 3 次点击、≤ 10 秒。

**设置与恢复**
- C16：把学期起始日改为上周一，首页周次读数 +1；节次表修改后课表网格行的时间刻度同步变化，且保存前出现过影响提示。
- C17：导出 JSON → 清空全部数据（需输入 `DELETE`）→ 导入刚才的文件，7 类记录条数与内容全部还原。

**健壮性**
- C18：在断网状态下打开应用，出现可读的错误态与重试按钮，不白屏、不出现未捕获异常。
