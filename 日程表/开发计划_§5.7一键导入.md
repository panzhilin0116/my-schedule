# §5.7 一键导入课表 · 开发计划（配套 PRD v2.2，2026-09-22）

> 本文件是 `PRD.md` §5.7「文字与图片 + 半自动」方案的可执行拆解，**不是开工令**。所有阶段在用户明确说"开工"之前不得动代码。P0 内含开工前置条件。

## 0. 总体技术选型（沿用现有栈，不引新框架）

| 决策点 | 选型 | 理由 |
|---|---|---|
| 框架 | **无**：继续 vanilla ES Modules + 现有 hash 路由/`h()` 渲染工具 | v2/ 全程零构建、零依赖，引框架等于重写；PRD §2 口径不变 |
| 数据存储 | localStorage 按空间键 `schedule.courses.v1.<空间ID>`；课程记录新增可选字段 `weeks? {from,to,parity}`、`importedFrom? 'import'` | §5.2/§5.6 已定稿；旧数据无这两个字段 = 全教学周 + 手加课，天然向后兼容 |
| 文字解析 | 自写纯函数（正则 + 分段启发式），零依赖 | 可全部在 node 下跑单测，样例 1 等真实文本做夹具 |
| 图片 OCR | **Tesseract.js（v6.x）+ chi_sim + eng**，文件手工 vendor 到 `v2/vendor/tesseract/`（无 npm）；Worker 线程跑识别 | 方案 B 定稿：图片不出设备；按需加载 + SW 缓存保离线 |
| 图片预处理 | 原生 Canvas 2D：缩放→灰度→对比度→（彩底白字）反色补跑 | 无依赖，浏览器内完成 |
| 网格重建 | 自写纯函数：输入 = OCR 文字块 `{text, bbox}` 数组，输出 = 星期×节次课表条目 | 与 OCR 解耦，可用合成 bbox 夹具在 node 下测 |
| UI | 复用现有浮层组件体系（`components/overlay` 模式、`courseForm.js` 的字段控件、Toast） | §2 全局交互约定：新建/编辑一律浮层 |
| 测试 | `node --test tests/*.test.mjs`（OfficePLUSAgent 自带 node.exe），DOM 用现有桩件 | 与现 92 条测试同构 |
| 部署 | Qoder Sites 静态发布 + Service Worker cache-first；**本次改动落地时 `sw.js` CACHE 必须升到 `schedule-v5`** | 历史教训：不升版本号老访客拿不到新文件 |

**vendor 具体清单（P0 手工下载，来源任选 unpkg / jsdelivr / 清华镜像，下载后记录来源与版本）**
- `tesseract.min.js`（约 60KB）
- `tesseract-worker.min.js`（worker 入口）
- `tesseract-core-simd.wasm.js` + `tesseract-core-simd.wasm`（约 3–4MB）
- `chi_sim.traineddata.gz`（约 2.5MB）、`eng.traineddata.gz`（约 4MB）
- 合计 10MB 上下，全部同源静态托管，**不进 git 也行（体积大），但发布包必须含**（Qoder Sites 上传目录 `v2/` 会带上）。

## P0 · 前置条件（无代码）

1. **开工令**：用户明确下令（历史要求，硬闸门）。
2. 夹具到位：文字样例 2/3（保留结构来源）；截图夹具再 2–3 张（电脑端教务/App）。样例 1 文本 + 截图已在手。
3. vendor 文件下载 + 本地起页面跑通一次 `recognize(样例1截图, ['chi_sim','eng'])`，记录：耗时、原始识别质量、彩底白字丢字情况 → 结论回写本文档 §P4 备注。
4. 环境确认：GitHub push 通道恢复（当前 ssh/443 连接重置，PRD commit `46ca010` 待补推）。

**完成标准**：4 项全勾；vendor 下载若全部镜像失败 → 向用户报告并商量替代（用户自下载放入目录）。

## P1 · 数据层升级（weeks + 周次感知冲突）

**改**：`v2/lib/courseStore.js`（或对应校验函数所在模块）、`v2/tests/courseStore.test.mjs`（新增用例）。
- `normalizeCourse`：接受可选 `weeks {from:int, to:int, parity:'all'|'odd'|'even'}`；非法结构 → 按缺省（全教学周）；`importedFrom` 透传。
- 新函数 `weeksOverlap(a, b)`：区间相交 && parity 兼容（`all`∩任意=真、`odd`∩`even`=假）。
- `findConflict(courses, candidate)` 升级为 **day 相同 && 节次区间重叠 && weeksOverlap**；手加课表单（§5.2 冲突报错）沿用同一函数，无 weeks 的课视为全周 → 行为与现状一致（回归重点）。
- `upsertCourse` 不改签名；导出 `removeImportedCourses()`（按 `importedFrom` 批量删）。

**完成标准**：新增单测 ≥8 条全绿（含：odd/even 并存不算冲突、无 weeks 旧数据行为不变、非法 weeks 归一化、清除只删带标记课），全量 `node --test` 通过。

## P2 · 文字解析器（纯函数）

**建**：`v2/lib/import/tokenize.js`（星期/节次/时间段→节次/周次/地点 token 识别，含 `08:00-09:35` 按 §5.1 模板换算就近开始节）、`v2/lib/import/parseText.js`（主入口）、`v2/tests/importText.test.mjs`。
- `parseImportText(text) → { items: PreviewItem[], unparsed: string[], positionLoss: boolean }`。
- `PreviewItem = { name, day?, startSection?, endSection?, room?, weeks?, color, status:'ok'|'needsFix'|'conflict', raw }`（预览层统一结构，**P6 网格重建输出同构**——这是两通道能共用预览的关键契约）。
- 来源探测：全文无任何星期/节次/时间 token 且 ≥2 对"课名↵地点"→ `positionLoss: true`，只产出半自动候选（name+room）。
- 表头噪声/空行过滤；一行多上课日拆多 item；解析规则逐条对 PRD §5.7 文案。

**完成标准**：夹具测试覆盖样例 1（判为 positionLoss 且 14 对候选齐全）、构造的教务整表复制样例、Excel 粘贴（制表符分隔）样例、时间段写法、单双周、噪声行；每条解析规则至少 1 断言；全绿。

## P3 · 导入浮层 · 文字线（UI 主体）

**建**：`v2/components/importOverlay.js`；**改**：`v2/views/timetable.js`（头部「⇋ 一键导入」+ 空态链接）、`v2/main.js`（如入口需注册）、样式 `v2/styles.css`（新粗野主义浮层清单样式，零圆角/硬阴影，遵守 design token 契约测试）。
- 三步状态机同浮层内切换：输入（文字/图片分段控件，图片段此阶段仅占位禁用提示"P6 上线"或隐藏——按开工时 P4 进度决定）→ 预览确认 → 写库。
- 预览清单：行内编辑（复用 courseForm 字段控件）、三态徽标、〔冲突〕实时按 P1 `findConflict` 对"已有课 + 清单内其他行"判定、默认不勾；「未能识别的内容」折叠区回显 `unparsed` 原文；〔确认导入 N 门课〕N 只计勾选且 ok 行。
- 写库：逐条 `upsertCourse` + `importedFrom:'import'`；StoreError Toast 沿用；完成后 Toast + 落脚课表页。
- 「导入的课程」徽标（课表详情浮层）+〔清除全部导入课〕（二次确认，调 P1 `removeImportedCourses`）。
- positionLoss 分支：不进步骤 2，显示提示文案 + 两条出路（换来源/图片模式；半自动入口在 P5 接通，先渲染按钮占位）。

**完成标准**：PRD §9 验收 22–28 逐条通过（浏览器实测；隐藏标签页限制：只用 `element.click()` 脚本驱动）；prompt 文案与 PRD 逐字一致；design.test.mjs 契约不破；全量测试绿。

## P4 · OCR 引擎加载 + 预处理（浏览器侧薄壳）

**建**：`v2/lib/import/ocr.js`、`v2/lib/import/preprocess.js`；`index.html` 不预载任何 vendor 资源。
- `loadOcrEngine(onProgress)`：dynamic `import()`/script 注入 `v2/vendor/tesseract/`；模块级单例缓存；失败 reject（P7 前 SW 未命中时走网络）。
- `recognizeImage(dataUrl, {onStatus}) → { words:[{text, bbox:{x0,y0,x1,y1}}], confidence }`：正常跑一遍 + （检测到大面积高饱和彩色块时）反色版补跑，按 bbox IoU 合并取字。
- `preprocess(dataUrl) → ImageData[]`：缩放上限（长边 ≤2000px）、灰度、对比度拉伸、反色；纯函数部分（像素运算）拆出来放 node 可测。
- 图片输入两条路：file input + 拖放 + 容器 focus 时 `paste` 事件（用户主动 Ctrl+V）；原件转 dataURL 即用即弃，**不写 localStorage**。

**完成标准**：样例 1 截图实测：14 门课课名/地点均出现在 words 中（允许个别错字，预览可改）；识别期间有进度显示、可取消；断网且 SW 未缓存时给出明确报错文案不白屏；像素纯函数有 node 单测。

## P5 · 半自动模式

**建/改**：`importOverlay.js` 增半自动步骤；`v2/components/courseForm.js` 增 `prefill` 入参（只增不改现有行为）。
- 两个喂入口：P2 positionLoss 候选、P6 网格重建失败时的 OCR 候选（课名+地点勾选清单）。
- 交互：勾选候选 → 逐条弹出（或内联展开）只含"星期 + 起始节次 +（可改的）节数"三个必填控件的迷你表单 → 通过即进预览清单（status ok，标 `importedFrom:'import'` 同权）。
- 文案：「识别到的课程需要你补选上课时间」。

**完成标准**：样例 1 文本走完全链路：粘贴 → 探测提示 → 半自动 14 条 → 逐条补时间 → 导入成功且网格落位与用户截图人工比对一致（验收 30 后半）。

## P6 · 网格重建（OCR words → 课表）

**建**：`v2/lib/import/grid.js`（纯函数）、`v2/tests/importGrid.test.mjs`（合成 bbox 夹具）；改 `ocr.js` 出口接 `grid.js` → 产出 `PreviewItem[]` 进 P3 预览。
- 锚点检测顺序：① 表格线（横平竖直长直线，从二值图投影找）→ ② 左侧节次号列（单字符数字 1–14 的 y 中心序列）+ 顶部星期行（`周一…周日` 或 `一…日` 的 x 中心序列）。任一失败 → 返回 `{ok:false}` 触发 P5 降级（验收 32）。
- 落格：每 word 中心点入"星期列 × 节次行"；同格 words 按 y 拼文本 → 课名/地点二分（地点 token 规则复用 P2 `tokenize.js`）；课名块纵向跨多格 → startSection/endSection。
- 置信度门槛：整图 mean confidence 过低或落格率 <60% → 判失败降级，不硬猜。

**完成标准**：合成 bbox 夹具（模拟样例 1 截图坐标分布）node 单测全绿：14 课落位与 ground truth 一致、周五综合法语实训(1)=第 6 节这类跨度判定正确；真实截图端到端（P4+P6+P3）验收 31 通过。

## P7 · 离线、SW、回归与发布

- `sw.js`：`CACHE` 升 **`schedule-v5`**；ASSETS 增补全部新 js/css；vendor 文件**不入预缓存清单**（10MB 不该给没用到图片功能的访客），改为 fetch 事件运行时缓存（成功响应写 cache，保离线复用）。
- `tests/robustness.test.mjs` 的 CACHE 断言同步改 v5。
- 全量回归：`node --test "tests/*.test.mjs"`（含原 92 条）全绿；§9 验收 22–33 逐条实测，33 的断网用例：先联网用一次图片模式 → 断网刷新 → 再识别成功。
- 发布：git commit（分阶段提交，消息带 §5.7 Pn）→ push（恢复的通道）→ Qoder Sites 发布流程（prepare_site → canPublish → publish_site → 验证 published）→ 线上冒烟：导入浮层开、文字样例解析、图片模式资源加载。

**完成标准**：验收 33 条全过；线上断网刷新站点可用；发布后 PRD §5.7 状态由"待实现"改为"已实现"（文档同步算收尾）。

## 里程碑顺序与工作量感觉

| 顺序 | 阶段 | 依赖 | 规模 |
|---|---|---|---|
| 1 | P0 | — | 半天（含等用户样例） |
| 2 | P1 + P2（可并行） | P0 | 各小 |
| 3 | P3 | P1,P2 | 最大的一块（UI） |

## 风险清单

1. **vendor 下载**：GitHub 443 已在重置，unpkg/jsdelivr/国内镜像需逐一验证（P0 第一件事）。全挂 → 请用户手机/PC 浏览器手动下载 5 个文件放入 `v2/vendor/tesseract/`。
2. **中文 OCR 质量**：错字可接受（预览可改），**丢块不可接受** → P0 冒烟就要验证反色补跑策略，必要时预处理加"按彩色块裁剪再逐块识别"的加强档。
3. **网格线检测脆弱**：教务截图无完整表格线时依赖节次列+星期行锚点；夹具只有 1 张时会过拟合 → 坚持再要 2–3 张不同来源截图后才宣布 P6 完成。
4. **10MB 首用下载**：进度 UI 必须如实 + 可取消；文案提前管理预期（"首次使用需加载识别引擎，约 10MB，之后离线可用"）。
5. **hidden-tab 验证限制**：浏览器自动化只能用 `element.click()`/同步脚本，验收脚本按此写。
