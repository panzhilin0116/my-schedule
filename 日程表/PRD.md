## 1. 产品目标和使用场景

**目标**：一名大学生管理自己的课程与日程：打开网页即可看今天的安排，30 秒内记下一条待办，手机和电脑都能访问，下次进入数据仍在。

**使用者**：站点公开，任何人打开链接即为一名使用者。**无注册、无登录、无第二角色、无协作**；每位访客进入时浏览器自动生成一个私有「空间」，不同空间的数据互不可见（见 §5.6）。产品仍按"单人管理自己"设计，不做共享。

**典型场景**

| 场景 | 设备 | 要完成的事 |
|---|---|---|
| 出门前扫一眼今天 | 手机 | 看今日课程、下一节倒计时、待办 |
| 课间想起一件事 | 手机 | 快速新建一条日程 |
| 晚上回宿舍安排明天 | 电脑 | 编辑日程、查看整周课表 |
| 想知道某节课在哪上 | 两者 | 查课表周视图 |
| 第一次进来还没有课 | 两者 | 在课表页把本学期课程录进自己的空间 |
| 教务系统里已有整张课表 | 两者 | 复制课表文本或截图图片 →「一键导入」→ 本地解析/识别 → 确认预览 → 填进课表（§5.7，已实现） |

**数据边界（已与用户确认接受）**：第一版不用数据库。日程与课程都存浏览器 localStorage，且**按空间隔离**——同一设备同一浏览器内持久；换浏览器/设备/清缓存后数据不保留；手机与电脑各自的空间互不可见。所有访客进入时看到的都是**空白课表**，需自行录入，任何人看不到别人的数据。

## 2. 整体页面框架和导航结构

- **形态**：托管静态网页（沿用现有站点），手机与电脑浏览器访问，无后端接口、无账号体系。空间隔离与数据持久化全部在浏览器 localStorage 完成。
- **页面**：3 个——首页 `#/`、课表 `#/timetable`、日程 `#/tasks`。Hash 路由。
- **导航**：断点仅 640px 一个。
  - 手机（<640px）：底部 3 Tab（首页/课表/日程），顶栏一行显示日期+周次。
  - 桌面（≥640px）：208px 左侧导航栏 + 内容区最大宽 960px 居中。
- **视觉**：深色液态玻璃（Liquid Glass）设计体系——具体色值与材质规范以 `v2/styles.css` 顶部 CSS token（`--base`、`--accent`、`--warn`、`--ok`、`--danger` 等）为准，由 `v2/tests/design.test.mjs` 契约测试把关。强调色低饱和，不抢内容；时间数字等宽。
- **全局交互约定**：
  1. 新建/编辑一律浮层：桌面居中 Modal（480px），手机底部抽屉（下拉关闭）；`Esc`/点遮罩关闭。
  2. 删除用 Toast「已删除 · 撤销」5 秒，不弹确认框。
  3. 每页具备空态（图标+引导语+主按钮）、骨架屏、错误态重试。
  4. 表单失焦即校验，非法时提交按钮禁用。

## 3. 首页的内容结构

自上而下 5 个区块：

1. **顶栏**：`2026-09-20 周日 · 第2周`；日期可点开只读迷你月历（标记有课/有日程的日期）。右侧有空间指示器：`空间` 标签 + 当前空间短 ID（末 4 位）+「新建空间」按钮（见 §5.6）。
2. **下一节卡（Hero）**：课程名+地点+「还有 HH:MM:SS」秒级倒计时；今日无课→「今日无课」；已全部上完→「今日课程已结束」。
3. **今日课程**：纵向时间轴；已过节次置灰，当前节青色左边框+「进行中」徽标；每行显示起止时间、课程名、地点。
4. **今日日程**：未完成置顶，点击圆圈直接勾选完成（划线置灰沉底）；条目显示时间段（若有）。
5. **临近日程**：明天起 3 天内，按日期分组，橙色日期标签。

## 4. 每个模块的用途

| 模块 | 用途 | 读写性质 |
|---|---|---|
| 首页 | 今日总览：下一节、今日课程、今日/临近日程一屏看全 | 课程只读；日程可读+可勾选完成 |
| 课表 | 展示并管理**本空间**的课程，回答"今天/某天有什么课、在哪上" | 读写（localStorage）：新增、编辑、删除课程；块详情可编辑 |

## 5. 每个模块第一版最必要的数据和操作

### 5.1 校历参数（内置常量）
- 第 1 周周一 = **2026-09-07**；教学周 **1–14 周**；无单双周。
- 作息时间表（节次网格以此为准）：
  1 08:00-08:45 / 2 08:50-09:35 / 3 09:50-10:35 / 4 10:40-11:25 / 5 11:30-12:15 / 6 14:00-14:45 / 7 14:50-15:35 / 8 15:50-16:35 / 9 16:40-17:25 / 10 17:30-18:15 / 11 19:00-19:45 / 12 19:50-20:35 / 13 20:40-21:25 / 14 21:30-22:15。

### 5.2 课表数据（localStorage，按空间隔离）

> v2.0 的"内置常量数组 12 条"已于 2026-09-21 整体下线（用户拍板：所有空间空白起步，本人的课也由本人重新录入）。

- 键：`schedule.courses.v1.<空间 ID>`（见 §5.6）；每门课结构：`{ id('c_' 前缀), name, day(1-7), startSection, endSection, room?, color, createdAt }`。
- v2.2 §5.7 生效后再扩展两个可选字段：`weeks?`、`importedFrom?`；缺省值与旧数据兼容规则见 §5.7。
- 字段规则：名称必填；星期必选（周一~周日）；节次取 5.1 作息模板 1–14，结束节次不得早于开始节次；地点选填；颜色从固定 6 色调色板（蓝/紫/绿/橙/青/粉）中选，默认轮询分配。
- 冲突检测：同星期节次区间与**本空间其他课程**重叠时，浮层内报错「与「XX」时间冲突」并禁用提交（编辑自身不算冲突）。
- 操作：课表页头部「＋ 添加课程」新建；点课程块弹详情，详情含节次起止、地点、覆盖周次说明与「编辑 / 删除」按钮；删除走 Toast「已删除 · 撤销」5 秒（含在编辑浮层内点删除的路径，撤销后即时回填网格）。
- 空态：新空间课表为空白，显示引导空态「这个空间的课表还是空的」+「添加第一节课」按钮。
- 节次模板与校历为全站统一常量，本期不做按空间自定义（已确认）。

### 5.3 日程数据（localStorage，按空间隔离）
- 键：`schedule.tasks.v1.<空间 ID>`；结构：`{ id, title, date, startTime?, endTime?, location?, note?, done, createdAt }`。
- 字段规则：标题必填；日期必填；起止时间选填且成对校验（有始必有终）；地点、备注选填。
- 操作：新建、编辑、删除（可撤销）、勾选完成/取消完成、按 全部/未完成/已完成 筛选；筛选态切页后保持。

### 5.4 课表页面布局
- 桌面：7 列 × 14 节网格，课程色块跨连堂行，红色 now 线。
- 手机：单日纵向时间轴 + 顶部星期胶囊横滑（默认今天），左右滑动切日。
- 概念图见 `PRD_第一阶段.md` 7.2 节。

### 5.5 日程页面布局
- 段控件（全部/未完成/已完成）+ 分组列表：**逾期 → 今天 → 明天 → 本周内 → 未来**；逾期橙条、今日/临近青条；右下悬浮「＋」。
- 概念图见 `PRD_第一阶段.md` 7.3 节。

### 5.6 空间机制（纯前端，无注册）
- 首次打开站点：自动生成空间 ID（格式 `sp_<时间戳36进制>_<随机6位>`，存 localStorage 键 `schedule.spaceId`），并落到当前 URL 会话；全程无需注册/登录。
- 所有个人数据键以空间 ID 作命名空间：`schedule.tasks.v1.<空间 ID>`、`schedule.courses.v1.<空间 ID>`；不同空间互不可见。
- 顶栏空间指示器：「空间」标签 + 短 ID（末 4 位大写，悬停显示完整 ID）+「新建空间」按钮。
- **新建空间**：二次确认后**清空本浏览器内当前空间的全部数据**并切换到全新空间（旧空间 ID 不保留、无法切回）。
- 坏数据保护：某空间数据被写成非法 JSON 时，页面显示错误态并可一键清空重置（沿用 §7 原有约定）。

### 5.7 一键导入课表 · 文字与图片（v2.2 新增，**已实现**，2026-09-22）

**定位**：把"一节一节手输"变成"整张课表喂进来"。两条输入通道 + 一条兜底：**① 文字粘贴**（教务/App/Excel 复制的文本，逐行启发式解析）；**② 图片识别（方案 B，本机浏览器内 OCR）**——用户上传或粘贴课表截图，OCR 出带坐标的文字块后重建网格，把文字复制会丢掉的星期/节次位置信息拿回来；**③ 半自动模式**（识别置信不足或来源丢位时的兜底，已认出的课名+地点预填表单，用户只补星期/节次）。**三条通道的结果统一进同一个"预览确认 → 写库"流水线。**

**隐私与网络边界**：文字与图片的解析/识别 100% 在本机浏览器完成，**用户的课表内容（文本与图片）不发任何网络请求、绝不上传**；唯一的外部依赖是首次使用图片识别时按需下载 OCR 引擎与语言包（公开静态资源，见"图片识别流水线"），下载内容不含用户数据。与 §5.6 空间隔离一致：导入结果只落当前空间。

**入口**
- 课表页头部「＋ 添加课程」旁增设次级按钮**「⇋ 一键导入」**（常驻，与课表空/非空无关）。
- 课表空态在现有引导按钮下追加次级链接「导入课表（文字或截图）」，打开同一浮层。

**浮层流程（三步，同一浮层内）**
1. **输入**：步骤内以分段控件切换两种模式——
   - **文字**（默认）：大号多行输入框，顶部提示文案固定为**「请复制您的课表并粘贴」**，下方灰色小字补充：`支持从教务系统/课程表 App/Excel 复制后直接粘贴，每行一条安排；内容仅在本机解析，不会上传`。
   - **图片**：虚线拖放/点选区，提示「上传或粘贴课表截图」，支持 `Ctrl+V` 直接粘贴剪贴板图片与文件选择器两条途径；选中后显示缩略预览，可更换/移除。小字注明：`截图在本机识别，不会上传；教务系统网页版或课程表 App 的课表页截图识别效果最好`。
   - 底部主按钮〔解析〕（无内容时禁用）。图片模式点〔解析〕进入"图片识别流水线"（见下），文字模式走"解析规则"。
2. **预览确认**：解析结果以**可编辑清单**呈现，每行 = 一条识别出的课程（字段同 §5.2：名称/星期/节次起止/地点/周次/颜色），行内可直接改正；三种状态徽标——〔已识别〕〔需修正〕（星期或节次缺失/非法，红色标出缺哪项，不修正该行无法勾选）〔冲突〕（与本空间已有课或清单内其他行按 §5.7"冲突规则"判定重叠，默认不勾选）。清单下方列出**「未能识别的内容」**折叠区，逐行回显原文，**永不静默丢弃**；一行含多个上课日（如教务"班课表"整行）拆为多条预览行。主按钮〔确认导入 N 门课〕，N = 勾选且状态合法的行数；另提供〔取消〕返回输入步骤（可改原文或换图重解析）。
3. **写库**：勾选项逐条走 §5.2 校验 + `upsertCourse` 写入本空间，每条打 `importedFrom: 'import'` 标记；完成后 Toast「已导入 N 门课 · 可随时编辑」并落到课表页。存储写满报 StoreError Toast（沿用现有）。

**解析规则（按行启发式，纯本地）**
- 星期：`周一/星期一/礼拜一/周1`（周一=1…周日=7）；无法判定星期的行 →〔需修正〕。
- 节次：`第3-4节/3-4节/030405节` 类节次号；或**时间段** `08:00-09:35/14：00~15：35`，按 §5.1 模板起始时刻换算为节次号（就近匹配开始节，换算不出 →〔需修正〕）。
- 周次：`第(1)-(16)周/1-16周/单周/双周` → 可选字段 `weeks {from, to, parity}`；缺省视为全教学周。
- 地点：匹配含 `楼/室/房/馆/区/中心` 或 `教学楼/实验/机房/体育` 等 token 的片段；剩下的第一段为课程名；两者难分时标〔需修正〕交给人。
- 表头噪声（`星期/时间/上午/下午/晚上` 及纯分隔线）、空行：忽略，不进未识别区。
- **来源探测（样例 1 教训，见下）**：解析先判定文本形态——若全文**没有任何星期/节次/时间 token**、只有"课名+地点"对（网格复制丢位形态），不进入逐行预览，而是给出明确提示「这种复制方式丢失了上课时间信息」，并引导两条出路：① 换保留网格结构的来源重新复制（推荐：电脑浏览器打开教务/用课表 App 的"导出/分享课表"功能），**或直接用"图片"模式上传该课表页的截图**（首选推荐，OCR 能拿回位置信息）；②〔半自动模式〕：程序已认出的"课名+地点"逐条预填进添加表单，用户只需为每条选星期和节次（比从零手输快）。**半自动模式纳入首期（2026-09-22 裁定）。**
- 解析纯规则实现、零依赖；以用户提供的**真实粘贴文本**做测试夹具，样例逐份归档如下。

**图片识别流水线（方案 B：本机浏览器内 OCR，2026-09-22 定稿）**
- **预处理（Canvas，纯本地）**：读入图片（file input / 剪贴板粘贴均转为 dataURL，不落盘不上传）→ 按原尺寸上限缩放 → 灰度化 + 对比度增强；对"彩底白字"课程块做亮度反色补跑一遍，两类结果合并。
- **OCR 引擎**：Tesseract.js + `chi_sim`+`eng` 语言包，**vendor 进仓库**（`v2/vendor/`，从 CDN 手工下载文件，本项目无 npm）；体积 4–10MB，**按需加载**（只在用户首次点图片〔解析〕时才拉取），加载进度如实显示；随 SW 缓存，下载一次后**离线可用**。语言包只认简中+英文，识别过程在本机 worker 线程跑，不阻塞 UI。
- **关键红利——坐标即位置**：OCR 输出每个文字块的 bounding box。据此做**网格重建**：检测表格线/或退而求其次用左侧节次号列（`1…14`）与顶部星期行（`周一…周日/一…日`）锚定行列 → 每个课名/地点文字块按**中心点**落进"星期×节次"格子 → 格内文本再走与文字粘贴同款的字段解析（课名/地点/节次跨度=块占的格行数/周次若格内或行首有标注）。**列 = 星期，行跨度 = 节次起止**——样例 1 里纯文本复制丢掉的信息，在像素层面还原。
- **结果汇入同一流水线**：网格重建成功 → 生成预览清单（同"预览确认"步骤，三态徽标、可编辑、〔冲突〕〔需修正〕规则全部复用）；用户预览确认前 OCR 原文不回显为最终结果，以清单为准。
- **失败与降级**（如实外显，不硬猜）：网格锚点检测失败或整图识别置信度过低 → 提示"未能从这张图里认出课表网格"，降级到**半自动模式**（把认出的"课名+地点"候选列出供勾选预填）；图片模糊/非课表 → 直接报错示例图指引（拍屏幕弱、截屏强的预期在文案里讲清楚）。识别失败不写任何数据。
- **质量口径（对用户的承诺上限）**：教务网页/App 的**数字截图**识别率高；**手机拍屏幕的照片**受摩尔纹/反光/透视影响明显变弱，只做尽力而为，不承诺。首期不做图片矫正（透视变换/去摩尔纹）。

**真实样例档案**
- **样例 1（2026-09-22，手机端教务课表页长按复制）**：结构 = 表头（`星期节次` + `一 9.21 … 日 9.27`）→ 节次号 `1…14` 竖排 → 之后为按"周列从上到下、列与列之间按周一→周日"平铺的 `课名↵地点` 对（本例 14 对）。**实测结论：课程色块在页面上是绝对定位绘制，纯文本复制后星期/节次信息完全丢失，逐行规则无法把课放回网格**；顺序虽呈列主序，但无每日边界锚点，不可靠。该样例作为"来源探测"的负例夹具保留；同时它证明了"课名+地点"两行一对的识别本身可靠，是半自动模式的可用输入。
- **样例 1 配套截图（同日，用户提供，`微信图片_20260922165028_51_31.jpg`）**：与上述文本同一张课表的手机端截屏，网格、星期表头、节次列完整可见，课程为彩色块白字。**作为"图片识别流水线"的第一个真实夹具**（网格重建 + 白字反色的回归样本）；14 对课的 ground truth 已人工比对过课表网格。再需 2–3 张不同来源的截图夹具（电脑端教务 / 课程表 App，**待提供**）。
- 样例 2、3（**待提供**）：文字通道需来自**保留结构**的复制源（电脑端教务网页 / 课表 App 导出文本 / Excel 复制），到位一份细化一份解析夹具。

**冲突规则（随本期升级 §5.2）**
- 仅当两门课**星期相同、节次区间重叠、且周次范围有交集**（`all`/同 parity 相交、`odd` vs `even` 不相交）才算冲突。
- 预览清单内部互冲、与已有课冲，均标〔冲突〕默认不勾；用户删改其一后可重新判定。

**导入后可管理性**
- 导入课与手加课完全同权（编辑/删除/撤销照旧），详情浮层对带标记课显示「导入的课程」徽标。
- 「一键导入」浮层检测到空间已有导入标记课时，输入步骤上方提供〔清除全部导入课〕（二次确认，只删带标记的课，手加课不动，无撤销、重导即恢复）。

**明确不做**
- **云端识别/上传解析（方案 A）**：图片与文字一律本机处理，不做后端 OCR、不发视觉模型请求（隐私、成本、匿名公开站的限流都不允许）。
- PDF/.xlsx 等文件导入（只收文字粘贴与图片位图）；**自动读取剪贴板**（一律用户主动粘贴或选文件，包括图片的 Ctrl+V 也须由用户发起）；图片透视矫正、去摩尔纹等增强（首期不做）。
- 跨空间共享导入结果；导入模板的"官方课表"分发（属已撤下的大一方案）。

**实现记录（2026-09-22，P1–P7，全量测试 154/154 绿）**
- 文字/半自动通道：验收 22–30 浏览器实测通过（含冲突双向判定、odd/even 并存、清除导入课、丢位文本降级）。图片与文字永不上传的口径不变：Network 面板实测仅同源静态资源请求，OCR 全程在 Web Worker 本机跑。
- 图片通道：Tesseract.js v6 五件套 vendor（约 10.7MB，不进 SW 预缓存清单、走运行时缓存，用一次后离线可复用）；正相+反相两遍识别按 IoU 合并；网格锚点=星期行/日期行（按学期日历反查星期）定列 + 竖排节次号定行；**内容质量门**：锚点在但课名大半是 OCR 碎片时整体降级半自动，绝不硬猜。
- **验收 31 尚未追认（如实记录）**：现有唯一截图夹具是"彩底白字 + 单元格文字被 App 截断（省略号）"的极端样本，实测触发质量门走了降级路径（即验收 32 的行为）。网格重建能力本身已由 14 门课合成 bbox ground truth 回归证明；31 需等 2–3 张更清晰的截图夹具（教务网页版全屏截图 / 课表 App 导出图）到位后补测，必要时上"按彩色块裁剪逐块识别"加强档（风险清单 2）。
- 样例 2/3（保留结构的文本复制源）**仍待提供**；解析器对既有夹具全绿，新夹具到位即补断言。

**优化轮记录（2026-09-23，响应用户两端实测反馈，全量测试 159/159 绿，SW 升 schedule-v6）**
- **电脑端「识别失败」根因**：Tesseract worker 按浏览器 SIMD 能力选核心文件，无加速指令集的浏览器（360/QQ 兼容壳等旧内核）请求 `tesseract-core-lstm.wasm.js/.wasm`——首轮 vendor 只备了 SIMD 对，非 SIMD 路径 404 → 整链失败。已补齐非 SIMD 回退对（vendor 增至约 16MB，仍只走运行时缓存）；引擎文件加载加一次自动重试，失败提示改为指明缺哪个文件的中文文案。线上已验证回退文件 200 可达。
- **手机端识别不准/错字**：① 加强档落地——`findColorBlocks` 按 8px 网格下采样检出彩底课程块，逐块裁剪、小块放大、`polarityToDarkText` 极性修正后单独识别，块内词按 IoU 优先并入整图结果（同分时块词压过整图糊词）；② 网格还原三修：星期表头行内错位单字（如截断日期 "9.2" 反查出假的周三）按"x 坐标下单调最长链"剔除、漏识的节次号按中位行距插值补回、chi_sim 拆出的中文单字碎片连写还原（"新 时 代"→"新时代"）；③ 半自动降级清单过滤星期表头以上的状态栏/导航栏杂行。
- 该极端截图夹具（截断白字）经加强后词级内容明显更全（状态栏杂项已滤除），但仍触发质量门走降级路径——**验收 31 维持"待追认"**，仍需 2–3 张清晰截图夹具。

## 6. 首页、今日计划和各模块之间的关系

- **课表 → 首页**：首页「今日课程/下一节」是对**本空间课表**（§5.2）按「当前周次(≤14) + 今天星期几 + 当前时刻」过滤排序的结果，不另存副本。周次 >14 或假期、或空间尚无课程时，首页显示"今日无课"。
- **日程 → 首页**：首页「今日日程」= `date == 今天` 的分组视图（未完成置顶）；「临近日程」= `明天 ≤ date ≤ 今天+3` 且未完成的只读摘要；逾期项不进首页，只在日程页橙条呈现。
- **首页 → 日程**：点首页日程条目跳转日程页并定位高亮该条；首页「＋」与日程页「＋」打开同一个新建浮层组件。
- **写入入口**：日程页/浮层可增删改日程；课表页/浮层可新增、编辑、删除课程（同空间）。首页只做勾选完成这一个写操作，不写课程/日程本体。三页读取当前空间的同一份 localStorage，多标签页打开时经 `storage` 事件同步。
